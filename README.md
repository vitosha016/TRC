# TRC × FRC — Game Center

Управление очередью баффов для Tiles Survive. Svelte 5 + Vite.

## Структура

```
├── scripts/              # Dev-скрипты (seed, fix-buff, test-api)
├── src/
│   ├── api/              # Бекенд на Google AppScript
│   │   ├── README.md                     # Инструкция по развёртыванию бэка
│   │   └── googleAppScriptBackend.gs    # Код AppScript (скопипастить в редактор)
│   ├── utils/             # Формулы (pure JS) + API-клиент + Svelte-сторы
│   │   ├── formulas.js
│   │   ├── formulas.test.js
│   │   ├── api.js
│   │   └── stores.js
│   └── components/        # Svelte-компоненты
│       ├── App.svelte           # Рут: header, копирование, лейаут
│       ├── AddForm.svelte       # Форма добавления/редактирования игрока
│       ├── GiverPanel.svelte    # Поле giver + топ донатеров
│       ├── BuffTable.svelte     # Таблицы Стройка / Исследования (2 колонки)
│       ├── LogList.svelte       # История транзакций (под details)
│       └── ui/                  # Stateless компоненты: Button, Card, Input, Select,
│           Suggest, SyncSpinner
```

## Как поднять бекенд

См. [src/api/README.md](src/api/README.md) — пошаговая инструкция.

Кратко:
1. Создать гуглотаблицу → Extensions → Apps Script
2. Скопировать код из `src/api/googleAppScriptBackend.gs`
3. Опубликовать как WebApp → скопировать ID
4. Прописать `PUBLIC_PROD_GOOGLE_APPSCRIPT_ID` в `.env`
5. `npm run build` → задеплоить `/dist`

## API

| Метод  | Параметр     | Назначение                                                    |
| ------ | ------------ | ------------------------------------------------------------- |
| `GET`  | `?type=all`  | Получить все данные (buffs, history, givers, nicks, template) |
| `POST` | `?type=save` | Сохранить изменения                                           |

Бекенд отвечает только за хранение. Вся логика подсчёта — на фронте.

## Архитектура UX

- **Оптимистичный рендеринг** — все действия (add/apply/delete) меняют локальное состояние мгновенно, без ожидания ответа бекенда. UI не блокируется, кнопки не дизейблятся.
- **Фоновая синхронизация** — запросы к GAS уходят в фоне (`Content-Type: text/plain` чтобы избежать CORS-preflight). Раз в 2 минуты — полная ресинхронизация `doLoad()`.
- **Плашка ошибок** — при сбое синхронизации загорается красная плашка снизу справа на 4 секунды, затем автосинхронизация восстанавливает состояние.
- **Острова** — карточки `Card`: форма + giver/донатеры в ряд (50/50), таблицы в ряд, история под раскрывашкой.
- **Автокомплит** — `Suggest` показывает всех при фокусе, фильтрует по мере ввода, клавиатурная навигация (↓↑/Enter/Esc).

<summary>Механика сортировки и 🔥-правила</summary>

### Приоритет очереди (scoreBuff)

Каждый игрок получает числовой **score** — чем выше, тем выше в очереди:

```
left   = max(0, endAt - now)
saving = round(left × applied / 100)          // накопленная экономия (для отображения)
score  = round(round(left × buff / 100) × boost)  // приоритет сортировки
```

- **boost** = 1.1 для Стройки, 1.05 для Исследований
- **buff** — процент баффа игрока (по умолчанию 15)
- **applied** — суммарный % уже выданных баффов

`saving` показывает **реальную экономию** от уже полученных баффов.
`score` используется для **сортировки** — предсказывает будущую выгоду от помощи.

### Буст донатерам

Топ-3 донатера (по количеству розданных баффов) получают множитель к score:
- **№1** — `score × 1.5`
- **№2-3** — `score × 1.25`

Сравнение ников — без учёта регистра (`toLowerCase()`).

### Сортировка

1. 🔥 **queueFire** — горящие игроки всегда наверху
2. **score** по убыванию (с учётом донатерского буста)
3. **left** по убыванию (при равном score)

### Правило 🔥 (queueFire)

Игрок получает 🔥, если **в его категории** (Стройка / Исследования):
- есть хотя бы один уже получивший бафф в этом круге (`queueReceived = 1`)
- **и** количество неполучивших ∈ {1, 2}

> То есть 🔥 загорается когда почти все в категории уже получили, а 1-2 ещё нет — им срочно нужен бафф.

### Применение баффа (applyBuff)

При нажатии 5%/10%/15%:
- `endAt = now + remaining × (1 − percent/100)` — оставшееся время сокращается
- `applied` += percent, `appliedCount` += 1
- `queueReceived = 1`, `queueLastAt = now`
- Создаётся запись в истории транзакций
- Обновляется статистика донора (givers)

### Экономия в таблице

Колонка «Экономия» = `round(left × applied / 100)`. Показывает совокупный эффект от уже выданных баффов. При `applied = 0` экономия равна нулю.

### Донатеры

Панель доноров показывает топ-8 игроков по количеству розданных баффов (горизонтальный скролл). Кулдаун донора — **3 суток** (259 200 сек). Если кулдаун не истёк — показывается оставшееся время, иначе «готов».
