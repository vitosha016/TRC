# Временный бекенд на Google AppScript

Бекенд сделан на гуглотаблицах (Google AppScript). **Никакой логики на беке — только хранение данных.** Вся логика подсчёта, сортировки и копирования — на фронтенде.

---

## Поднятие бэка

### 1. Создать новую гуглотаблицу

Зайди в Google Sheets, создай пустую таблицу.

### 2. Открыть AppScript

Меню: **Расширения → Apps Script**

### 3. Скопировать код

Скопируй **весь** код из файла `src/api/googleAppScriptBackend.gs` и вставь в редактор.

### 5. Опубликовать WebApp

[Инструкция по деплою](https://seoneurons.com/create-contact-us-page/#34-deploying-the-script-as-a-web-app)

- Нажми **Развернуть → Новое развертывание**
- Тип: **Веб-приложение**
- Доступ: **Все (в том числе анонимные)**
- Нажми **Развернуть**

После деплоя скопируй **Идентификатор развертывания**.

### 6. Прописать переменную окружения

Создай файл `.env` в корне проекта и добавь:

```env
VITE_GAS_ID=<идентификатор_развертывания>
```

### 7. Сбилдить и задеплоить

```bash
npm run build
```

Артефакты из `/dist` залить на хостинг (Vercel, Netlify, Cloudflare Pages и т.д.).

### 8. Заполнить таблицу

После первого запроса скрипт **автоматически создаст** нужные листы:

| Лист | Назначение |
|------|-----------|
| `Buffs` | Очередь баффов (id, nick, type, buff, endAt, ...) |
| `History` | История выдач (id, recipient_id, recipient, type, giver, percent, time) |
| `Givers` | Статистика доноров (nick, total, last_buff) |
| `Nicks` | Сохранённые ники (nick) |
| `Template` | Шаблон копирования в чат (key, value) |

Ничего заполнять вручную не нужно — данные попадают в таблицы через API.

## API — два эндпоинта

Все запросы на один URL веб-приложения с параметром `?type=`.

### GET `?type=all`

Возвращает **все данные** разом:

```json
{
  "ok": true,
  "buffs": [...],
  "history": [...],
  "givers": { "nick": { "total": 1, "last_buff": 1234567890 } },
  "nicks": ["nick1", "nick2"],
  "template": {
    "header_build": "#184 Стройка | {date}\r\n",
    "limit_build": 15,
    "header_research": "\r\n#173 Исследование\r\n",
    "limit_research": 15,
    "include_5": 0,
    "header_5": "#186 Для ускорений стройки отдаём баффы 5%\r\n"
  }
}
```

### POST `?type=save`

Сохраняет любую комбинацию данных. Тело:

```json
{
  "buffs": [...],            // полный массив → заменит лист Buffs целиком
  "historyEntry": {...},     // одна запись → добавится в конец History
  "giverStat": {             // обновит счётчик и дату для указанного ника
    "nick": "Vi007",
    "ts": 1234567890
  },
  "nick": "Vi007",           // добавит ник если нет
  "template": {...}          // заменит шаблон
}
```

Можно передать одно поле или сразу несколько. Ответ содержит **свежие данные** всех таблиц после сохранения:

```json
{
  "ok": true,
  "buffs": [...],
  "history": [...],
  "givers": {...},
  "nicks": [...],
  "template": {...}
}
```

## Как это работает с фронтендом

1. Фронтенд при загрузке делает `GET ?type=all` — получает все данные
2. Все вычисления (`scoreBuff`, `rankBuffsForQueue`, `getQueueFireIds`, `generateCopyText`) делаются **на фронте**
3. При применении баффа:
   - Фронтенд сам считает новый `endAt`, `applied`, `appliedCount` и т.д.
   - Отправляет `POST ?type=save` с обновлённым `buffs`, новой `historyEntry` и `giverStat`
4. Бекенд просто записывает что дали

## CORS

Google AppScript WebApp **не поддерживает** CORS-заголовки напрямую.

**Варианты решения:**
- **Прокси на уровне хостинга** — Vercel/Netlify могут проксировать запросы к GAS
- **CORS Proxy** — для локальной разработки
